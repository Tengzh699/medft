# V5：医疗问诊数据与偏好训练

本轮针对自由回答的问诊质量，不沿用医学选项考试成绩证明问诊提升。旧的考试adapter及其结论保留；V5从原始Qwen2.5-7B-Instruct重新初始化LoRA。

方向沿用教程的症状采集、分诊、检查选择、报告解释、知识问答和拒答边界；本轮重点放在前两项的事实状态与行动顺序，检查、报告和常识作为保留检查。增加有效信息及错误对照，不追求重复填满6000行。

## 数据改动

训练有184组成对回答：28类情境各6个状态，另有8条知识/信息边界和8条可验证读数题。184组来自44个分组，并非184个真实独立患者。每组同时保存完整的较好回答、明确有错的回答、偏好理由和来源。

六个状态是：当前危险、当前较轻、未来假设、明确纠正病史、病情新近恶化、信息尚未提供。组内各分支始终放在同一划分，避免把同一病例换个说法就当未见验证。

较好回答应体现当前事实、适当紧急程度、先行动还是先追问，以及必要的观察和复诊安排。错误回答用于对比学习，例如忽视新发危险、把未提供的信息视为阴性、将课堂假设当真实病史、建议等到明天。**错误回答不能被当作SFT目标。**

全部是工程编写的教学材料，依据公开健康信息解释行动边界；不是医生标注、真实诊疗记录或临床金标准。来源页面保存在`data/raw/consultation-v5-evidence/`并记录哈希。正文未复制成训练答案；中文对话为原创，急救渠道按中国120/110作本地化。药物处理保留在个人已有医嘱及急救指导范围，不重新给出个体处方剂量。

## 训练方法

使用缓存原始基模参考概率的DPO，加0.1权重的较好答案SFT项。只监督最终assistant回答，历史assistant和用户内容屏蔽；配对顺序固定为较好/错误。与标准答案选项训练不同，这里输出完整自然语言。

NF4、q/v层、LoRA r8/alpha16，学习率2e-5，2轮，有效batch8。参考概率在与策略模型相同的k-bit准备之后计算，避免非量化层dtype转换导致参考数值不一致。专用实现及梯度、监督mask和配对顺序有测试。

```powershell
python scripts/build_consultation_preferences.py
python scripts/train_consultation_preferences.py --config configs/v5_consultation.yaml
```

发布的数据和实验输出不覆盖；训练已有目录时会报错。此配置应使用专用脚本，通用`medft train`不实现DPO。

## 冻结与验收

固定4类其他病种的24组验证回答，按其偏好验证损失选择checkpoint。另留8类不参与训练或checkpoint选择的病种，共32段自然对话；同病种分支相关，不能当32个独立患者。冻结哈希和预定处理规则在`outputs/consultation-v5/protocol.json`。

原36题继续使用原评分、原256-token上限及单条推理，属于开发回归。新32段对话两方使用相同384-token上限与batch，保存原始输出，逐条检查当前事实、行动时机、风险升级、实用性和危险附加建议。不通过关键词命中数宣称临床准确率。

完整强度若未通过原36题内容检查，可按训练前规则检查一次0.5强度；不能根据新32段最终结果再换强度或checkpoint。前轮已使用的CMExam最终测试不参与本轮选择，也不重新宣称为未见数据。

验收必须同时报告改善和退化。若输出仍出现危险建议，记录具体原文，不设为默认问诊模型。专业审核和更广泛、独立临床场景评估仍是后续工作。

## 实验结果

V5完成46步、2轮训练，用时512.4993秒，固定24组验证损失由0.8078215降至0.7089962，导出checkpoint-46。118项测试及来源/权重核对通过；原104份受保护产物未改。

| 原36题开发回归 | 原规则通过 | 内容结论 |
| --- | ---: | --- |
| 基模 | 31/36 | 保留原始回答与既有问题 |
| V5完整强度 | 33/36 | 新增严重单位方向错误，危急值仍含等待路径，不通过 |
| V5 0.5强度 | 31/36 | 恢复部分回答，但危急值行动仍含糊，不通过 |

完整强度第26题把肌酐100 mg/dL称为可能偏低；第30题在危急值加明显不适时引入线上初步意见及条件等待。第17题将当前幕布样视野缺损的立即行动弱化为进一步严重时才急诊。0.5强度消除了前两类中的单位方向与眼科时机退化，但危急值仍未可靠修复。这说明规则分数提高不能代替内容检查。

两档全部72条原始回答均已阅读。逐题对照、内容决定、训练及审计在`outputs/consultation-v5/`。本轮未设为默认模型，也未使用新32段留出对话挑模型。继续修订的数据见[V5.1最小改动对照](CONSULTATION_V5_1.md)。
