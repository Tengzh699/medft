# 第二篇教程的6000条数据复现

可以先扩充数据，旧adapter评测不是前置条件。此阶段使用独立配置 `configs/v1_6000.yaml`，沿用第二篇的种子、槽位、模板生成路线，对齐**总计6000条，训练5600条、验证400条**。固定12道独立评测题另计。

## 现在执行

在已激活的medft环境和项目根目录依次运行，不需要下载数据或重新下载模型：

```powershell
python -m medft generate-data --config configs/v1_6000.yaml
python -m medft build-data --config configs/v1_6000.yaml
python -m medft preview --config configs/v1_6000.yaml --split train --limit 2
```

第一条组合候选数据，第二条清洗、去重并按病例组划分，第三条查看训练样例。也可将最后一条的 `--split train` 改为 `--split validation` 查看验证样例。

## 数据怎样达到6000条

种子文件为 `assets/v1_6000_seeds.jsonl`，345条种子记录对应170个知识/场景组：

| 类别 | 种子内容 | 每组变体 | 总量 |
| --- | --- | ---: | ---: |
| 知识问答 | 120个主题：复用原30个，补充90个 | 20种问法前缀 | 2400 |
| 多轮问诊 | 25个症状场景，每组6个年龄、病程与诱因槽位组合 | 每槽位8种问法×两轮/三轮交互 | 2400 |
| 拒答/高风险求助 | 25个场景，每组3种具体请求 | 每请求16种问法 | 1200 |
| 合计 | 170个组，345条种子记录 | | 6000 |

新增主题涉及检验指标、影像局限、药物常识、睡眠、运动、饮食、口腔、眼耳健康及就诊信息等。问诊覆盖头痛、咳嗽、腰背痛、皮疹、排便变化等，保留追问、补充情况、建议与红旗症状。高风险场景优先及时求助，不仅训练拒答。

这些内容由工程编写，状态均为 `unreviewed`，没有调用LLM接口，也未宣称来自指南或真实患者。问法前缀和整理就诊信息的轮次属于模板扩写，6000行不等于6000个独立知识点或临床病例。此配置用于复现教程的数据规模与训练流程，医学内容仍需复核。

种子资产可通过 `python scripts/build_v1_6000_seeds.py` 复现；日常运行上述三条命令即可，不必额外重建种子。

## 如何精确划分5600/400

同一知识主题的所有问法、同一问诊或拒答场景的所有槽位和问法共享 `case_id`。划分还合并相同首问及公开备用问法，防止这些关联样例跨集合。

`data.split_counts` 指定精确条数，优先于比例。程序在保持完整组的条件下选取400条验证数据，并尽量接近各任务比例；无法凑足或清洗后不足6000条时会报错，不能靠拆组或重复补齐。当前结果如下：

| 集合 | 知识问答 | 问诊 | 拒答/高风险 | 合计 | 病例/主题组 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 训练 | 2240 | 2208 | 1152 | 5600 | 159 |
| 验证 | 160 | 192 | 48 | 400 | 11 |
| 总计 | 2400 | 2400 | 1200 | 6000 | 170 |

总量严格为40%/40%/20%。整组隔离会让验证集比例有所变化，不能同时强行要求每一份都满足40%/40%/20%。同一组不会跨集合，但不同主题仍可能存在语义关联；这不是完整的语义去重，也不能把小型模板验证集当作临床效果评估。

`test_ratio: 0` 代表不另切测试集，因此该配置不生成 `test.jsonl`。训练只检查启用的训练/验证两份文件，`preview --split test` 会明确报未启用。

## 产物与后续训练

- `data/generated/v1-6000/corpus.jsonl`：6000条候选。
- `data/generated/v1-6000/preparation.json`：种子数量、任务比例、来源、组数及哈希。
- `data/processed/v1-6000/train.jsonl`：5600条。
- `data/processed/v1-6000/validation.jsonl`：400条。
- `data/processed/v1-6000/stats.json`：清洗、分组与文件哈希。

检查统计与样例后，正式训练使用：

```powershell
python -m medft train --config configs/v1_6000.yaml
```

默认3轮、batch_size为1、梯度累积8；5600条完整可用时每轮约700次优化器更新。输出到 `outputs/v1-6000/`，正式训练会计算验证loss并保存checkpoint。这里没有替用户启动训练。

原50条配置、774条公开混合配置和已有adapter各自保留。774条混合语料可用于后续公开数据对照实验；当前6000条配置的公开数据数量为0，先对齐第二篇的合成路线。之后再扩展第一篇的症状采集、分诊、检查建议和报告解读。
