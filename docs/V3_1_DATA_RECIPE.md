# V3.1完整答案数据方案

本轮由编码助手在用户授权下执行数据生成、工程筛选、真实3090训练和同条件评测。正式配置为 `configs/v3_1_complete_grouped.yaml`；开发回归题及其评分未改。

## 为什么重建

V3生成结果中，短追问和短拒答替代了基模原有的完整解释，出现遗漏实际份量计算、危险症状后继续等问题、检查准备擅自推断等情况。仅降低学习率的C组仍低于基座。这轮改进目标是完整回答、信息一致性与保留原有解释能力；不是增加重复样本行数。

## 实际构成

先生成225条工程编写样本，包括24条完整普通解释、8条拒答/风险帮助、12种情境的5种信息状态，以及模拟报告、单位换算和包装份量计算。直接风险、恶化、假设、当前否认、更正病史共享病例身份；数值答案从输入字段计算。模拟参考区间明确属于虚构机构，不能作为通用诊断阈值。

另用同一个本地基模，针对原种子中的180个知识问题生成完整回答，保留原文、模型revision、结束标记、生成参数和seed身份。工程阅读筛除70条存在明显问题、答非所问或需要进一步专业核实的记录；8条未正常生成结束，未进入训练。102条保留为能力回放，仍是基模生成的未审核候选，不能作为医学金标。

合并327条后，去掉6条完全重复的对话，得到321条：

| 任务 | 清洗后条数 |
| --- | ---: |
| 知识问答 | 166 |
| 报告解读 | 79 |
| 症状采集 | 36 |
| 分诊 | 24 |
| 检查建议 | 8 |
| 拒答/风险帮助 | 8 |

其中219条为工程编写，102条为筛选的基模回放。没有重复补齐到6000条；增加独立知识和场景需要额外来源与审核。

## 隔离和事实检查

正式划分训练272、验证49。除相同病例、开场问题外，标准化后相同的完整最终答案也用 `answer_group` 连在同组。最初版本发现两种最终答案跨集合，已中止训练并保留在 `outputs/v3-1-complete/`；正式运行使用新目录 `outputs/v3-1-complete-grouped/`。

审计确认训练/验证的病例、组、完整用户消息、完整最终答案均无完全相同交集；与原12题、原36题和新增29题的完整用户消息也无完全相同交集。**这不是主题或语义完全隔离**：不同措辞仍可能考察相同概念，模板片段也仍然复用。验证集较小，验证loss不足以认证效果。

计算与状态约束测试核对实际份量算术、物理量上限、参考方向、缺失字段、当前/假设风险、跨任务同答案分组及原始候选保留。紧急症状概念参考公开NHS页面，原文和HTTP状态保存于 `outputs/optimization/source-evidence/`；只用于核对概念，训练答案为工程编写的中文，急救渠道按中国120/110表述。此过程没有医学专家审核或临床标签认证。

## 训练与评测

从原始Qwen2.5-7B-Instruct新建LoRA，未继续训练已退化的adapter；r=16、alpha=32、全部原投影层，学习率1e-5、最多2轮68步、每10步验证、按分组验证loss选最佳已保存checkpoint，patience=3。实际最长498 tokens，无超长跳过。

原36题保持为主要开发回归。新增29题在这轮模型训练前冻结，额外检查份量计算、趋势、危险行动和普通解释；它与本轮课程同由编码助手编写，属于开发检查，不能称为盲测或独立临床验收。

基座和adapter均使用原system prompt、贪心解码、最多256新tokens、seed=42及raw输出。原规则不改；除总分，还逐题检查事实、当前与条件性行动及普通问答是否丢失。数据、学习率和训练轮数同时改变，所以最终差异不能单独归因于某一个因素。

## 已完成的V3.1结果

原36题多要点基模31/36、V3.1为28/36；新增29题为18/29与19/29。原36题禁止模式从0变为1；逐题还发现猜测单位、算术及急救条件等实际错误，不能将本轮称作整体改善。完整记录见[V3.1评测复核](V3_1_EVALUATION_REVIEW.md)。

后续`configs/v3_2_strength_control.yaml`复用完全相同的321条数据和272/49分组，单独测试更强的训练更新：学习率1e-4、最多3轮，仍按验证loss选已保存checkpoint。两组开发题已被查看，后续成绩不得标成盲测。协议保存在`outputs/optimization/v3-2-strength-protocol.json`。

## 文件与重建

- 生成：`scripts/build_complete_data.py`、`scripts/generate_base_replay.py`。
- 筛选：`scripts/finalize_base_replay.py`、`assets/complete_replay_exclusions.json`；原始180条候选全部保留。
- 数据：`data/generated/v3-1-complete-grouped/`、`data/processed/v3-1-complete-grouped/`。
- 审计：`outputs/optimization/complete-grouped-data-audit.json`、`base-replay-screening.json`、`v3-1-grouped-plan.json`。
- 评测冻结与实验协议：`outputs/optimization/complete-evaluation-freeze.json`、`complete-experiment-protocol.json`。

已有基模回放文件时，可用 `python scripts/build_complete_data.py --group-answers` 重建相同数据。已发布的源文件若与重建结果不同，脚本拒绝覆盖；正式训练和评测也要求选择空输出目录。
