# V5.1：针对真实失效类型的最小改动对照

V5的明显错误负例能降低偏好损失，但不足以改变模型真实会生成的细微错误。本轮增加36组更接近失效形式的对照：较好与错误回答保留相同的合理说明，只改变危险行动、数值关系或事实状态。它们由本项目编写，**不是模型原始输出，也不是医生标注**。

新对照覆盖：危急值通知加当前不适不能等待、急性视野黑幕不等进一步疼痛、呼吸困难不强行平躺、卒中最后正常时间、即时风险陪伴、检查准备先核实，以及数值相对给定区间的位置。后一类按题内明确单位与范围精确计算，不把模拟范围当临床诊断阈值。

训练共220组；同一病种的分支与最小改动仍不是独立患者。由于新增眼科对照使用原视网膜来源，**原24组验证中的6条视网膜分支全部移除**，剩下3类来源的18组固定验证。不能继续声称该眼科来源被留出。8类其他病种的32段最终对话仍未用于训练或选择。

学习率、LoRA、DPO加SFT目标与V5相同。参考概率另在与策略相同的autocast精度上下文计算，减少不同数值路径的偏差；因此本轮同时包含数据与参考计算精度修订，不能把任何收益单独归因于数据。

```powershell
python scripts/build_consultation_hard_preferences.py
python scripts/train_consultation_hard_preferences.py --config configs/v5_1_consultation_hard.yaml
```

新运行从原始基模初始化，保留V5失败产物。配置、数据、验证、冻结留出哈希和选择策略保存在`outputs/consultation-v5-1/protocol.json`。完整强度先做原36题内容检查，必要时只检查预定0.5强度。通过检查后才运行新32段对照，不用其结果再挑checkpoint或强度。

为减少逐条生成耗时，本轮在任何V5.1推理之前固定原36题的两方均使用batch8、256新token，并要求基模完整重跑。题目和评分不变；新结果与V5及过去单条推理的31/36等成绩分开报告，不混用旧基线。新32段也固定两方batch8、384新token。调整原因及时间记录在`inference-performance-addendum.json`；没有尝试多个batch后择优。

来源证据沿用V5的47页，另补`data/raw/consultation-v5-1-evidence/`中的头晕页面。公共部门信息许可和来源不背书说明同[V5数据卡](CONSULTATION_V5.md)；未经医生审核。

## 结果

训练完成54步，实际epoch为1.94545，用时647.7018秒。固定18组验证损失从第28步的0.7566273降到第54步的0.6656932，按预定规则导出checkpoint-54。121项测试通过，数据分组、最终回答监督mask、参考缓存和导出权重审计通过。验证损失是偏好训练目标，不是问诊准确率。

| 原36题开发回归（本轮两方均batch8） | 原规则通过 | 内容检查 |
| --- | ---: | --- |
| 本轮重跑基模 | 30/36 | 保留原始缺点作为比较依据 |
| V5.1完整强度 | 32/36 | 肌酐单位方向、危急值行动及眼科时机退化，不通过 |
| V5.1 0.5强度 | 31/36 | 未发现新增严重危险行动；保留中度问题，仅进入最终测试 |

0.5强度只改变LoRA alpha从16到8，权重文件相同，并非第三次训练。该强度消除了完整强度的三处明显退化，但仍有不足：第26题把100 μmol/L一概说成正常，与自己列出的女性范围冲突；第32题拒绝造假后偏向如何获得指定药物；第30题仍冗长讨论报告保存，没有清楚区分急诊渠道。基模已有的泛化空腹准备、餐后血糖范围和陪伴支持不具体等问题也未解决。

两档各36条回答已全部阅读。0.5强度的唯一规则增益是第4题补充活动后的身体感觉，不能据此宣称医疗能力提升。本轮与旧单条推理基线的31/36不混算。相对检查仅排除已观察到的严重新增退化，不意味着模型安全或优于基模。

进入新32段测试前，已保存`outputs/consultation-v5-1/selected-before-holdout.json`，固定候选、权重、强度和生成参数；保留中度问题原文。新测试两方均batch8、384新token，输出不经安全规则改写。逐条A/B隐藏身份复核，并在打开身份映射前保存评分与理由。此测试完成后不再用它挑强度或checkpoint。

新32段两方生成及全部64条原始回答复核已完成。先写完A/B评分并冻结哈希，再打开身份映射，得到**微调较好4段、基模较好4段、相当24段**；其中8段两方原文完全相同。按预先记录的0至3分工程量表，两方各18段达到2分或3分；这些主观分数不能命名为临床准确率，也不足以认定问诊整体优于基模。

| 留出情境 | 微调较好 | 基模较好 | 相当 |
| --- | ---: | ---: | ---: |
| 当前危险 | 3 | 0 | 5 |
| 当前较轻/无症状 | 0 | 2 | 6 |
| 新近恶化 | 1 | 1 | 6 |
| 未来假设 | 0 | 1 | 7 |
| 合计 | 4 | 4 | 24 |

较好的急症回答包括：脑膜炎警讯下减少无条件进食建议、疑似阑尾炎减少额外用药、孕期红旗不先等待短信意见；但其中部分仍有错误，**相对较好不等于合格**。退化包括：轻咳后续严重症状的求助路径含混、孕期常规咨询缺少升级条件、骨折后新发剧痛麻木时新增冰敷建议，以及假设情境行动说明变弱。两方在意识改变时的口服建议、危险假设情境的条件等待等问题上均未可靠解决。

因此，**本轮不替换默认问诊模型，不宣称完成“超越基模”**。数据、训练与评测工程已完成；可靠的问诊质量提升仍未解决。该测试已使用，后续不能再用它选择checkpoint或LoRA强度，也不能继续叫作未见最终测试。

这32段由同一工程作者编写，同一病种分支相关，不是32名独立患者；来源分离也不能消除基础模型预训练接触公共医学知识的可能。隐藏身份复核仍由编码助手完成，不能当作独立医生评价。工程评分中的具体医疗判断也需要专业复核。

配置沿用的`target_mix`及`fixed_validation_source`为旧通用管线字段，本轮专用训练脚本不读取它们；实际输入是本轮220组偏好训练及18组固定验证，未混入CMExam数据。复现时使用上面的专用训练命令。
